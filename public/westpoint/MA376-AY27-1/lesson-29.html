What We Did: Lessons 20 to 28

NoteReview: Judging a Classifier (Lesson 20)
Truth positive Truth negative
Predicted positive TP FP, a false alarm
Predicted negative FN, a miss TN
  • Accuracy \(= \dfrac{TP + TN}{n}\)
  • Sensitivity (recall) \(= \dfrac{TP}{TP + FN}\), specificity \(= \dfrac{TN}{TN + FP}\)
  • Precision \(= \dfrac{TP}{TP + FP}\)
  • \(F_1 = \dfrac{2\,TP}{2\,TP + FP + FN}\)
  • Cut probabilities into labels at a threshold. \(0.5\) is a default, not a rule.
NoteReview: Class Imbalance and Prevalence (Lesson 21)
  • Rare outcome: the null classifier scores \(1 - \text{prevalence}\), and a \(0.5\) threshold flags almost nothing.
  • Three fixes: move the threshold, class weights (glm(..., weights = w)), undersample. Each one moves the cutoff. None improves the model.
  • Sensitivity and specificity do not move with prevalence. Precision does.
  • Report performance with the prevalence it was measured at.
NoteReview: Rater Agreement and the ICC (Lesson 22)
  • Percent agreement \(p_o\). Chance agreement \(p_e = P(A)P(B) + P(A^c)P(B^c)\)
  • Cohen’s kappa \(\kappa = \dfrac{p_o - p_e}{1 - p_e}\): agreement once you remove chance. Falls as prevalence moves to an extreme.
  • \(\text{PABAK} = 2p_o - 1\): kappa with the prevalence set at half
  • ICC \(= \dfrac{\hat\sigma^2_{\text{subject}}}{\hat\sigma^2_{\text{subject}} + \hat\sigma^2_{\text{rater}} + \hat\sigma^2_{\text{error}}}\), from a two-way ANOVA with raters as blocks
  • Reliability is not validity: raters can agree and all be wrong.
NoteReview: Fixed, Random and Mixed Effects (Lesson 23)
  • \(y_{ij} = \mu + u_j + \varepsilon_{ij}\), \(u_j \sim N(0, \sigma^2_u)\), \(\varepsilon_{ij} \sim N(0, \sigma^2)\)
  • lmer(y ~ 1 + (1 | group), data = d), then fixef(), ranef(), coef()
  • \(\hat y_{ij} = \hat\mu + w_j(\bar y_j - \hat\mu)\), \(w_j = \dfrac{n_j}{n_j + \lambda}\), \(\lambda = \dfrac{\hat\sigma^2}{\hat\sigma^2_u}\): small groups shrink toward the average
  • \(\text{ICC} = \dfrac{\hat\sigma^2_u}{\hat\sigma^2_u + \hat\sigma^2}\)
  • Fixed: these levels are all you care about. Random: the levels are a sample of many.
NoteReview: Mixed-Effects Logistic Regression (Lesson 24)
  • \(\log\dfrac{p_{ij}}{1 - p_{ij}} = \mu + u_j\), \(u_j \sim N(0, \sigma^2_u)\). No \(\varepsilon\): pass or fail is the noise.
  • glmer(y ~ x + (1 | group), family = binomial, data = d)
  • predict(fit, newdata, type = "response", allow.new.levels = TRUE)
  • glm with a dummy per group: a group at 100% gets \(\hat\beta \to \infty\). glmer shrinks it.
  • \(\text{ICC} = \dfrac{\hat\sigma^2_u}{\hat\sigma^2_u + \pi^2/3}\)
NoteReview: Trees and Random Forest (Lesson 25)
  • A tree splits the data into boxes. Each split picks the predictor and cut that lowers Gini impurity the most.
  • Gini for a box: \(G = 2p(1 - p)\). After a split, average the two boxes, weighted by size.
  • A tree grown all the way memorizes the training data and does worse on new data. Limit it.
  • Random forest: many trees, each on a bootstrap sample, each split choosing from mtry random predictors. The forest votes.
  • randomForest(y ~ ., data = train, ntree = , mtry = , nodesize = ); tune on out-of-bag \(F_1\).
  • predict(fit, newdata, type = "prob") gives the share of trees that vote yes.
  • Variable importance says which predictors the forest leans on, not how.
NoteReview: Model Competition (Lesson 26)
  • Six model types on the Memo 4 leads, scored on \(F_1\) of the call column.
  • Logistic at \(0.5\) calls nobody: about 97% accurate, \(F_1 = 0\).
  • Tune the cut on train (five-fold cross-validation) or on the forest’s out-of-bag votes. Never on test.
  • Check on test, then refit on all 12,000 before you predict the incoming leads.
  • Calls \(= TP + FP\). The recruiters can make 1,230.
NoteReview: PCA, the Model (Lesson 28)
  • No \(y\). PCA builds new columns from the \(x\)’s: \(Z_m = \phi_{1m} X_1 + \phi_{2m} X_2 + \dots + \phi_{pm} X_p\)
  • Loadings \(\phi\): squares sum to 1. \(Z_1\) is as spread out as possible; \(Z_2\) the same, uncorrelated with \(Z_1\); and so on.
  • pca <- prcomp(d, scale. = TRUE): pca$rotation loadings, pca$x scores, summary(pca) shares
  • Scale first. Scaled, the total variance is the number of columns.
  • The sign of a component is arbitrary. Read each \(Z\) by its biggest loadings.
  • Biplot: dots are scores, arrows are loadings.

  • Today: how many components to keep.

Proportion of Variance Explained

Scaled, each column has variance 1, so the total is \(p = 4\).

\[ \text{PVE}_m = \frac{\text{Var}(Z_m)}{\text{total}} = \frac{\text{Var}(Z_m)}{p} \]

  • In summary(pca) above, Proportion of Variance is the PVE. Cumulative Proportion is the running total.

How Many Do We Keep?

  • PCA gives as many \(Z\)’s as columns: 4 here. Keep all 4 and we still have 4 numbers per state. Nothing gained.
  • The point is fewer numbers: keep the top few \(Z\)’s, drop the rest.
  • Each one we drop loses its PVE. So keep enough to hold most of the variance, and stop when the next one adds little.
  • How do we see where to stop?

The Scree Plot

pve_tbl <- tibble(component  = 1:4,
                  pve        = summary(pca)$importance["Proportion of Variance", ],
                  cumulative = summary(pca)$importance["Cumulative Proportion", ])

pve_tbl |>
  pivot_longer(c(pve, cumulative), names_to = "type") |>
  mutate(type = if_else(type == "pve", "PVE", "Cumulative PVE")) |>
  ggplot(aes(component, value)) +
  geom_line() +
  geom_point(size = 3) +
  facet_wrap(~ fct_rev(type)) +
  scale_y_continuous(limits = c(0, 1), labels = scales::percent) +
  labs(x = "Principal component", y = NULL) +
  theme_minimal()
  • Left: the scree plot. Look for the elbow, where the drop flattens out.
  • Here it bends at 2: after \(Z_2\) each one adds little.
  • Right: two components keep 86.8%; three keep 95.7%.
  • No single right answer. ISLR: eyeball the elbow, and keep components you can interpret.
NoteScree?

Scree is the pile of loose rock at the bottom of a cliff. The plot looks like a cliff, then the rubble.
